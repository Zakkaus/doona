## Editing behavior and shared code

- Connect places the duck and name above the card, with URL/token inputs,
  primary Connect, an or divider, secondary demo action, and language/colour
  controls below. Initial HTML colours match the site theme.
- Nodes lists protocol, available address metadata, and provenance. Import
  checks each share link with backend syntax validation before saving the
  complete batch. Manual edits reuse `src/dae/nodes.ts`; ambiguous declarations
  and references in another source block renames/deletes. Share links are
  cleared when their dialog closes.
- Subscriptions adds name/URL editing, confirmed deletion, refresh one/all, and
  a retry list for unconfirmed refresh results. It reuses
  `src/dae/subscriptions.ts` and group reference checks. Duplicate declarations
  refuse edits. Subscription names remain fixed in the edit dialog.
- Groups creates, renames, and deletes groups; edits native policy values;
  selects named nodes, subscription tags, or explicitly all nodes. No selected
  members means no matches. Advanced filters remain intact. It reuses
  `src/dae/groups.ts`, `groupFilters.ts`, and `groupConditions.ts`.
  The round 2 member dialog retains TCP/UDP selection and return-to-automatic.
- Routing retains Rule/Direct/Global and adds an interactive rule list with
  a condition builder, token values, fallback selector, and a text fallback.
  It validates before review. Its before/after display reuses the UI-free
  `src/features/rules/diff.ts`; block helpers use `src/dae/ruleText.ts`.
- DNS edits upstream URLs and request/response rules interactively, with the
  same text fallback, validation, and diff review. No unrelated block can be inserted.
- Global Settings exposes all 34 fields in `src/api/engines/honkSettings.ts`,
  grouped by `src/dae/settings.ts`. It uses that module's value validation and
  surgical serializer. The single Settings dialog also controls language and theme.
  App preferences apply immediately; global edits validate, show a diff in the
  same modal, then use the existing If-Match, settle and reread path.
- The navigation footer displays backend identity and lifecycle/reload state. It rereads
  after actions; it does not poll or display observability metrics.

The full-app node/subscription hooks and `view.ts` import UI/store modules and
cannot enter this bundle. Their completeness, uniqueness, and reference rules
are adapted around the UI-free DAE helpers. No XHTTP-specific form is added;
the share-link editor preserves the complete link.

Configuration writes verify the source hash, validate the complete source set,
write with If-Match, settle the operation, and reread. Validation diagnostics
remain visible. Stale snapshots refuse writes. Runtime group selection and
subscription refresh use their existing API contracts and reread after actions.
Capability gates disable writes with a reason. Buttons show pending state;
results use Toast, and errors also remain inline.

## Limits

- Real-backend writes were not exercised; verification uses the shared mock.
  The requested mock end-to-end workflow has no missing endpoint.
- The Node API does not expose subscription-node addresses. Manual links
  provide address metadata. Node forms omit protocols honk rejects, including SSR
  and HTTP/HTTPS proxies.
- Editing targets the main source. Ambiguous declarations, cross-source
  references, and multiple same-name routing/DNS blocks refuse unsafe edits.
- Honk treats legacy `min` and `random` as selector policies. The editor states
  that behavior. API validation remains authoritative.
- Settings that require a process restart are disabled with an explanation beside
  the field. Honk's write contract rejects these before storing; it exposes no
  save-without-reload mode. Hot settings such as check_tolerance remain editable.
- Row actions use one ghost small MoreMenu with a row-specific accessible name.
  Subscription refresh temporarily replaces it with a loading action.
- A shared selection map distinguishes automatic (success) and manual/pinned
  (accent). Policy labels are translated; tooltips retain the native keyword.
- Subscription addresses show an em dash and explanatory tooltip because honk
  does not expose them. Manual node addresses are parsed from their share links.
- The mobile settings tabs do not shrink their labels. Long table header actions
  wrap as a unit so the page title does not split inside a word.
- Theme previews rebind core colour tokens inside each nested Theme. This keeps
  the light miniature light even when the surrounding app uses dark mode.
- Vite reports a non-fatal raw-chunk-size advisory. Private project code still
  needs the owner's publication decision. Round 7 dependencies are listed below.
